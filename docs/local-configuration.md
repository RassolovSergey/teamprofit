# Локальная конфигурация TeamProfit

Сервер рассчитан на .NET 8 и PostgreSQL. Публичный `Server/appsettings.json` содержит только общие настройки. Ключ Fixer, ключ подписи JWT и строка подключения к БД в нём пустые.

## .NET User Secrets для разработки

В `Server/Server.csproj` задан `UserSecretsId`. При окружении `Development` стандартный `WebApplication.CreateBuilder` загружает секреты из пользовательского каталога вне репозитория.

Из корня проекта задайте свои значения вместо заполнителей:

```powershell
dotnet user-secrets set "Jwt:Key" "<YOUR_NEW_RANDOM_JWT_KEY>" --project Server/Server.csproj
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "<LOCAL_POSTGRESQL_CONNECTION_STRING>" --project Server/Server.csproj
dotnet user-secrets set "FixerApi:AccessKey" "<NEW_FIXER_KEY>" --project Server/Server.csproj
```

Для JWT используйте собственный случайный ключ достаточной длины для HS256, минимум 32 байта. Не используйте заполнители из инструкции в работающем приложении.

User Secrets предназначены для разработки и не шифруются. Не добавляйте их файл в Git и не копируйте серверные ключи в Blazor-клиент.

## Переменные окружения

Стандартная конфигурация ASP.NET Core также понимает `Jwt__Key`, `ConnectionStrings__DefaultConnection` и `FixerApi__AccessKey`. Двойное подчёркивание обозначает вложенный раздел.

`.gitignore` исключает локальные файлы `.env`, `secrets.json` и `appsettings.*.local.json`, однако приложение не загружает `.env` или произвольные локальные JSON-файлы автоматически. Используйте User Secrets либо переменные окружения.

## Обновление курсов

Регистрация фонового обновления курсов в `Server/Program.cs` сейчас закомментирована. Пока служба выключена, ключ Fixer для неё не используется. Перед включением задайте новый ключ и проверьте настройки API. Сам URL запроса с ключом не следует записывать в журналы.

## Ранее опубликованные значения

Удаление значения из Git не отзывает его у провайдера. Любой действующий опубликованный ключ нужно отключить или заменить в соответствующем сервисе. Также замените пароль БД и JWT-ключ, если эти значения использовались в доступном окружении. Замена JWT-ключа делает ранее выданные токены недействительными.

Перезапись истории меняет SHA коммитов. После очистки старую копию проекта лучше заменить новым клоном. Не сливайте старую историю обратно. Копии у других людей и кешированные страницы GitHub могут сохранять старые данные, поэтому очистка истории не заменяет отзыв ключа.
